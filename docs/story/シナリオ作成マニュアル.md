# ストーリー作成ツール 操作マニュアル

このマニュアルでは、地域地図・人物・会話・戦闘を作り、成果物をゲームのプロジェクトへ配置するまでを説明します。現時点では作成したシナリオJSONの編集・検証までが使えます。ゲーム内で会話や戦闘を再生し、完了状態を保存する機能はまだ接続されていません。

## 1. フォルダーの役割

```text
NengouGuesser/
├─ index.html                         ゲーム本体
├─ questions.json                     戦闘用問題データ
├─ named-cpus.json                    ネームドCPUデータ
├─ database.rules.json                RTDBルール案（Firebaseへ自動反映されない）
├─ story/
│  ├─ data/
│  │  ├─ story-world.json             世界・地域・ステージの基準データ
│  │  ├─ story-characters.json        ストーリー人物の基準データ
│  │  └─ scenarios/                   書き出したシナリオプログラムの保管場所
│  ├─ studio/
│  │  ├─ story-world-studio.html      世界地図・地域・ステージ編集
│  │  ├─ story-character-studio.html  人物設定
│  │  └─ story-scenario-studio.html    シナリオ・イベント作成
│  └─ assets/
│     ├─ ancient-world-map.jpeg       世界地図
│     ├─ shinden.jpg                  幣殿の背景
│     └─ regions/                     地域別地図画像
└─ docs/story/                        仕様・更新履歴・このマニュアル
```

画像は従来どおりプロジェクトのルートからの相対パス（例：`story/assets/regions/mesopotamia.jpg`）でも指定できます。各画像欄の「画像を取り込む」ボタンからファイルを選ぶ方法にも対応しました。取り込んだ画像はデータURLとして各JSONに埋め込まれます。PNG・JPEG・WebP・AVIF・GIFに対応し、1ファイル8MBまでです。

## 2. HTMLを開く

各HTMLをFinderから直接開く `file://` 方式では、ブラウザーがJSON読み込みを止めることがあります。プロジェクトのルートで簡易Webサーバーを起動し、そのURLから開いてください。

1. ターミナルでプロジェクトフォルダーへ移動します。
2. `python3 -m http.server 8000` を実行します。
3. ブラウザーで次のURLを開きます。
   - 地図編集: `http://localhost:8000/story/studio/story-world-studio.html`
   - 人物編集: `http://localhost:8000/story/studio/story-character-studio.html`
   - シナリオ作成: `http://localhost:8000/story/studio/story-scenario-studio.html`
4. 終了時はターミナルで `Control+C` を押します。

編集ページはブラウザーの下書きにも自動保存しますが、これは同じブラウザー内だけです。成果物を残すには、各ページの「JSONを書き出す」を必ず使ってください。

## 3. 時代別の世界地図・都市・地域・ステージを作る

`story-world-studio.html` を開きます。

1. 上部の「表示する時代」で、古代・中世・近世・近代・最近世・現代を切り替えます。
2. 「この時代の世界地図画像」は、パスを入力するか、隣の「画像を取り込む」ボタンからファイルを選びます。取り込んだ画像はJSONに埋め込まれるため、画像ファイルを別途コピーする必要はありません。既存の `story/assets/ancient-world-map.jpeg` などの相対パスも引き続き使えます。
3. 「＋ 都市」で都市を追加します。都市名・ID・所属地域（任意）・注記・地図上のX/Y座標を設定します。座標は0〜100で、現在選択している時代の地図上にピンとして表示されます。
4. 「＋ 地域」で地域を追加します。地域名、時代、世界地図上のX/Y座標、初期開放状態を設定します。地域ピンは、その時代の地図に表示されます。
5. 地域の地図画像も同様に、地域地図画像欄の「画像を取り込む」から選択できます。相対パスを直接入力する方法も残しています。空欄なら既定の地形表示になります。
6. 「＋ ステージ」で地域内の地点を追加します。ステージ名、順番、シナリオID、地図上のX/Y、初期開放・隠し設定、開放条件を設定します。
7. ステージ地図プレビュー上の点の並びが、ゲーム内の点線ルートになります。点の座標も0〜100です。
8. 「JSONを書き出す」で `story-world.json` をダウンロードします。内容を確認して `story/data/story-world.json` を置き換えます。

都市と地域は時代別に管理されます。所属地域を指定しない都市は、その時代の世界地図に直接配置されます。画像取り込みを使った場合、画像データはJSONに埋め込まれます。世界地図と地域内地図は、書き出した `story-world.json` をゲーム側の同名ファイルへ反映すると表示できます。都市ピンのゲーム画面への反映は、現時点では未接続です。

地域を追加したあと、その地域にステージを作り、シナリオIDを決めてからシナリオ作成画面へ進むと参照がつながりやすくなります。既存データを置き換える前に、元のJSONを別名でバックアップしてください。

**現時点の接続範囲:** ゲーム本体は `story-world.json` の時代別世界地図画像と地域地図画像（相対パス／取り込み済みデータURL）を表示できます。都市データのピン表示はまだゲーム本体に接続されていません。

## 4. 人物を登録する

`story-character-studio.html` を開きます。

1. 人物を追加し、固定IDと表示名を設定します。IDは英数字と `_` を使い、重複させません。
2. 「対戦CPUとの接続」で、人物を対戦相手にもする場合は一覧から既存のCPUプロフィールを選びます。接続状態とCPU名・IDがその場に表示されます。物語専用NPCなら「CPUと接続しない」を選びます。人物IDとCPUプロフィールIDは別のIDです。
3. チャットアイコン、通常のノベル立ち絵、標準背景、7種類の表情別立ち絵は、それぞれの欄の「画像を取り込む」から選べます。相対パス入力も引き続き利用できます。
4. 登場条件、イベントタグ、役割、メモを設定します。表情画像は「嬉しい」「悲しい」「怒る」「驚く」「無表情」「困る」「ニヤつく」の7種類です。プレビューで登録画像を確認できます。
5. 検査に問題がなければ「JSONを書き出す」で `story-characters.json` を出し、`story/data/story-characters.json` を置き換えます。

人物IDはシナリオJSONから参照されます。あとでIDを変えると、既存シナリオの人物参照も修正が必要です。

## 5. シナリオ・会話・戦闘を作る

`story-scenario-studio.html` を開きます。地図、人物、問題、ネームドCPUのデータを読み込んでいることをページ上部の状態表示で確認します。

1. 「＋ シナリオ」でシナリオを作成し、タイトル、配置ステージ、時代、順番、説明、次に開放するシナリオを設定します。
2. 会話だけなら「＋ 会話イベント」を使います。表示形式は、背景・0〜3人の立ち絵・字幕を組み合わせるノベル形式、またはアイコン横にメッセージを表示するチャット形式です。
3. 戦闘を含めるなら「＋ 戦闘セット」を使います。戦闘前交流、問題を使う戦闘、戦闘後交流がセットで作成されます。
4. ノベル形式では、人物を0〜3人配置し、各セリフの話者と表情を指定します。表情欄で「嬉しい」などを選ぶと、人物Studioで登録した対応画像がプレビューに反映されます。プレビューは最後に編集したセリフを表示します。選択した表情画像が未登録なら、個別立ち絵、通常のノベル立ち絵の順に代替します。背景と各人物の個別立ち絵も、欄の「画像を取り込む」から選べます。戦闘イベントでは、人物StudioでCPUプロフィールと接続した人物名がCPU候補の横に表示されます。
5. 「参照を確認」で、存在しないステージ・人物・問題・イベントIDや不整合を確認します。
6. タイトル名のJSONを書き出し、`story/data/scenarios/` に保管します。複数のシナリオを作る場合は、シナリオごとのJSONを残してください。

現状、ゲーム本体は `story-world.json` と人物設定を読みますが、`story/data/scenarios/` のシナリオプログラムを実行する再生機能は未接続です。したがって、書き出したシナリオJSONは制作データとして保管・共有し、将来の再生機能接続後に利用します。JSONの書き出しだけでゲーム内にシナリオが追加された状態にはなりません。


### 特別エリア「廻間」「幣殿」のステージ

`story-world-studio.html` の「特別エリアのステージ」欄で、通常の時代別地域とは別に「廻間」「幣殿」を選択できます。各エリアに複数のステージを追加し、ステージ名・ステージID・シナリオID・表示順・地図座標・初期開放・隠しステージ・開放条件を設定します。

設定は `story-world.json` の `metadata.specialAreas` に保存されます。各エリアの `stages` 配列にステージオブジェクトが入ります。既存の `metadata.voidMap` と `metadata.specialStages` は互換性のため保持します。特別ステージを追加したらJSONを書き出し、`story/data/story-world.json` を置き換えてください。

注意：この編集機能は特別エリアの制作データを保存するものです。ゲーム本体側で `metadata.specialAreas` を読み込んでステージ選択・進行に反映する接続は別途必要です。

## 6. 更新をゲームへ反映する

編集で使う基準ファイルは次の場所です。

- 地図・地域・ステージ: `story/data/story-world.json`
- 人物: `story/data/story-characters.json`
- シナリオ: `story/data/scenarios/<シナリオ名>.json`
- 画像: `story/assets/` 以下

地図・人物JSONをエクスポートしたら同じ名前の基準ファイルへコピーして置き換えます。取り込んだ画像はJSON内に含まれるため、別途画像ファイルをプロジェクトへコピーする必要はありません。相対パスを使う場合は、従来どおり画像ファイルも `story/assets/` 以下などへ配置してください。シナリオJSONはまだ本編から読み込まれないため、`scenarios` に保管します。

GitHub Pagesで公開する場合は、`index.html`、`story/`、`assets/`、`questions.json`、`named-cpus.json` など必要ファイルを含むプロジェクト一式をリポジトリへ反映します。HTML単体やJSON単体だけでは動きません。更新後はブラウザーで再読み込みし、画面と開発者コンソールで読み込みエラーがないことを確認します。

## 7. Googleアカウント連携とFirebase

この版ではFirebase AuthenticationのGoogleプロバイダーを使い、最初の端末では匿名ゲストUIDをGoogle認証へリンクします。別端末では「Googleアカウントから復元」を押します。既存のGoogleアカウントを選ぶと、端末内とクラウドの進行フラグを統合します。「進行をクラウドへ保存」は手動操作です。頻繁な自動書き込みや常時監視はしません。

Firebase Consoleで確認する項目：

1. Authentication → Sign-in methodでGoogleを有効化し、サポートメールを設定。
2. Authentication → Settings → Authorized domainsに公開サイトのホスト名を登録。例：`electroon0701.github.io`。`https://`やパスは含めません。ローカル確認では`localhost`も許可します。
3. Realtime Database → Rulesに`database.rules.json`の内容を反映。公開済みルールへ手作業で加える場合は、`storySaves/$uid`の読み書きを`auth.uid === $uid`に限定するルールを追加します。ルールが公開されていないとGoogleログイン後のクラウド保存・復元でPermission deniedになります。
4. GitHub PagesなどHTTPSの公開URLから試します。OAuthポップアップは`file://`では動作しません。

この実装は各操作時にFirebase接続と小さな進行JSONの読み書きを行います。Firebase Sparkで利用でき、課金プランへの自動変更はしません。Sparkの保存容量・通信枠には上限があるため、むやみに連続クリックせず、通常は連携時と節目の手動保存にしてください。Firebaseルールの変更はオンライン対戦にも関わるので、公開前に現在のルールをバックアップしてください。

## 8. よくある問題

- **JSONが読み込まれない**: `file://`で開いていないか、サーバーをプロジェクトルートから起動したか、ファイル名と場所が合っているか確認します。
- **地図画像が見えない**: 取り込み済みデータURLか、相対パスの大文字・小文字、拡張子、プロジェクトルート基準の指定を確認します。大きな画像は1ファイル8MB以下にしてください。
- **シナリオが地図に結びつかない**: 地図側とシナリオ側のステージIDが完全一致しているか確認します。
- **Googleログインが失敗する**: Googleプロバイダー、承認済みドメイン、HTTPS、ポップアップ許可を確認します。
- **ログインするが同期できない**: Realtime Database RulesがFirebase Consoleへ公開されているか、自分自身のUIDだけ読み書きできるルールになっているか確認します。
